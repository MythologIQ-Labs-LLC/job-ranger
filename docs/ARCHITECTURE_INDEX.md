# Canonical Architecture Index

**Authority:** canonical routing document for Sojourner architecture decisions (repository `MythologIQ-Labs-LLC/sojourner`, renamed from `job-ranger` on 2026-11-02; on the same date the owner decided that every package, storage, archive and build identifier is renamed to Sojourner too, with existing users' data migrated, see ARCH-002).  
**Effective decision:** 2026-10-16 (owner direction); ARCH-001, ARCH-002 and ARCH-006 amended 2026-11-02 (owner direction: Windows first); ARCH-005 amended 2026-11-02 (owner decisions: the Windows app's Drive export uses a Google Desktop OAuth client; the Windows app gets a Storage location for backups and documents on this computer, Google Drive or OneDrive).  
**Status:** active on `main` since PR #335 (2026-10-16).

## Mandatory resolution rule

**All normative architecture interpretation starts here.** This index identifies the document authoritative for each architecture domain. A document, issue, draft, historical ADR, old release note, or implementation plan that contradicts the effective decisions here **is superseded for architecture** and must not be used to authorize new design or release obligations.

The index is the **single architecture decision router**, not a claim that every linked document is already internally consistent. Where an older canonical document contradicts an explicit current decision below, the supersession below controls until its source document is revised. Document conflicts must be flagged and corrected; do not silently infer authorization from contradictory text.

Truth is still distinguished by type:
- **Architecture policy:** this index and the active, index-designated normative documents.
- **Implemented capability:** exact current `main` source and tests; these may show legacy code, not permission to ship it.
- **Published reality:** actual publicly available build/deployment and tested behavior, not release plans.
- **Planned work:** proposals and draft branches are nonauthoritative until approved and integrated.

## Effective, binding decisions

| ID | Decision | Consequence |
| --- | --- | --- |
| ARCH-001 | **A signed Windows application is the primary product deliverable; the Progressive Web App continues as the universal, cross-environment channel.** Sojourner: Employment Toolkit (historically Job Ranger) ships first as a Windows installer. The browser PWA, including the bounded interactive demonstration linked from MythologIQ Studio, is kept and must not regress. | Windows releases are the Electron NSIS installer, Authenticode-signed with the MythologIQ Labs Azure Artifact Signing profile (publisher `MythologIQ Labs, LLC`) under the [Windows code signing standard](https://github.com/MythologIQ-Labs-LLC/Myth-Tech-Forge/blob/main/docs/WINDOWS_CODE_SIGNING_STANDARD.md). They are built and signed only by `release-build.yml` from a release tag, after owner approval of the `release` environment, which holds the GitHub OIDC sign-in (no client secret). Microsoft Store, macOS and Linux native packages stay out of scope unless separately approved. |
| ARCH-002 | **Electron is the Windows product runtime and remains the shared-core engineering harness.** | Electron test lanes are Windows release gates. The installed app's identity is Sojourner throughout (owner decision 2026-11-02): appId `com.mythologiq.sojourner`, data folder `%APPDATA%\Sojourner` (Store: `Sojourner Store`), database `sojourner.sqlite3`, `.sojourner` archives. Existing data is never abandoned: at first start the app copies the legacy folder (`%APPDATA%\job-ranger` / `Job Ranger Store`), verifies the copy and uses it, falling back to the untouched legacy folder on any failure (`electron/src/legacy-migration.cts`); the installer removes a legacy Job Ranger install (old appId `com.jobranger.app`) keeping its data (`build/installer.nsh`); `.jobranger` archives still restore. |
| ARCH-003 | **Demo is a deliberately limited real PWA experience**, separate from claims of full product availability. | Studio is a marketing/link handoff, not a second application runtime. Demo data must be identified and isolated; features not supported in browser must not be promised. Hosting and Studio production edits require explicit owner approval. |
| ARCH-004 | **Canonical career data stays user-owned and deterministic.** | Providers, agents, inference and external services cannot silently promote unverified facts, mutate canonical career truth, mass-apply or upload career data without specific human consent. |
| ARCH-005 | **Google Drive export, when shipped, requires a runtime-appropriate OAuth flow and explicit artifact-level approval.** | **PWA:** authorization only on the separately hosted helper origin with a Google Web OAuth client; the access token stays in volatile page memory; browser credentials cannot rely on a packaged client secret. **Windows (Electron):** a Google Desktop OAuth client, the system browser, PKCE (S256) and a single-use state on a `127.0.0.1` loopback redirect (RFC 8252); the refresh token may persist only encrypted with Windows `safeStorage` (never in SQLite, logs, URLs, archives or the renderer; session-only when encryption is unavailable), and the access token stays in main-process memory. **Both:** scope `drive.file` only; explicit approval of exactly one verified PDF on every export; no automatic sync; one shared state machine (`src/shared/artifact-export-*.ts`) and export flow (`src/shared/drive/drive-export-flow.ts`); Drive is hidden when the build lacks its client configuration; nothing but the approved PDF and Google authorization calls leaves the device; disconnecting deletes the stored sign-in and revokes it at Google (best effort). Acceptance of one runtime never substitutes for the other. **Windows storage locations (owner decision 2026-11-02, [contract](./design/STORAGE_LOCATIONS.md)):** the Windows app alone may copy automatic and manual workspace backups (full `.sojourner` archives) and exported documents to one person-chosen location: a local folder, Google Drive (`drive.file`, a `Sojourner` folder, #369's Desktop sign-in) or OneDrive (Microsoft identity platform public client, tenant `common`, PKCE on a `http://localhost` loopback, scopes `Files.ReadWrite.AppFolder` and `offline_access` only, Graph app folder only). This automatic backup copying is the one exception to "no automatic sync"; resume export to Drive still needs per-file approval. The working database always stays local (no live multi-PC editing); restores use the existing validate, stage and restart path; refresh tokens follow the same `safeStorage` custody; no telemetry. The **PWA** keeps its local backup UI, gains none of this, and its helper-origin Drive export stays merged but off; there is **no hosted mythologiq.studio OAuth helper**. |
| ARCH-006 | **No unqualified publication claims.** | PWA browser production build, origin, service worker, persistence, privacy and security must be verified before an externally accessible demo or release is announced. A Windows installer is called signed only after `signtool verify /pa` passes with signer `MythologIQ Labs, LLC` and a timestamp, recorded in the release evidence. |

## Commercial brand decision boundary (owner update: 2026-10-28)

**The owner-selected product identity is Sojourner, displayed as `Sojourner: Employment Toolkit`.** This replaces the former public-facing name `Job Ranger`. The October 16 pending-name instruction and earlier Pathwise/Trailmark candidate research are superseded for **product naming** by [issue #339](https://github.com/MythologIQ-Labs-LLC/sojourner/issues/339). MythologIQ Labs, LLC remains the corporate maintainer.

**Implementation approval is not a trademark-clearance or production-deployment approval.** The 2026-11-02 owner decision renames package/runtime identifiers, desktop and PWA storage names, the service-worker identity and the archive extension to Sojourner, each with a migration that keeps existing users' data (ARCH-002); legacy `.jobranger` archives still restore and historical release links stay as they are. Make user-visible Sojourner copy and cohesive replacement artwork in one bounded, reviewed rebrand candidate; do not ship a mixed old-name/Sojourner UI, reset existing user data, or rename OAuth redirect origins or signing IDs as a cosmetic operation. New public hosting, Studio production changes, DNS, trademark representations and launch communication retain their separate approval gates. The runtime decision is ARCH-001 (Windows first, PWA continuing, since 2026-11-02); Google Drive delivery scope is unchanged.

## Change control

1. Propose changes through a reviewed PR that changes **this index first or in the same atomic PR** as any designated canonical domain document.
2. Record decision, reason, effective date, prior authority, affected interfaces, supersession and verification evidence.
3. Update index links and affected user-facing documentation in the same delivery slice. Do not leave contradictory normative entries knowingly active.
4. A draft PR, issue comment or older architecture plan cannot silently override this index. Raise the conflict for explicit review.
5. Do not repurpose unrelated historical documents as current policy, and do not delete implementation/test evidence merely because product distribution changed.
